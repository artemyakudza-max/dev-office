# AGENTS.md — памятка проекта

## Игра
«Выживи на совещании» — браузерная мини-игра: Вова на совещании листает мемы на телефоне, пока босс не смотрит. Продержаться 60 секунд, не получить 2 замечания.

## Технологии
- Vanilla HTML/CSS/JavaScript (ES2020+), **без сборки и фреймворков** (решение из design/decisions.md)
- Сцена: Canvas 2D, UI: DOM поверх canvas
- Весь баланс и тексты — в `js/config.js`, не в коде

## Как запустить локально
Открыть `index.html` в браузере (двойной клик) — проект статический, сервер не нужен.
Если что-то не работает без сервера — `python -m http.server 8000` в папке проекта, открыть http://localhost:8000

## Как проверить код
- Ошибки смотреть в консоли браузера: F12 → Console (десктоп)
- На телефоне: подключить кабель, Chrome → chrome://inspect (Android) или Safari → Develop (iOS)
- Синтаксис JS: `node --check js/<файл>.js` (Node.js установлен через winget)

## Обязательный цикл работы ИИ (для каждого шага)
1. **Сделать задачу** (код/ассеты/конфиг). Без самопроверок ИИ (запусков скриптов, автотестов, превью) — их не делать: проверяет пользователь. **ВСЕГДА обновлять версию игры**: увеличить `version` в `js/config.js` (например v0.9.27 → v0.9.28) в каждом изменении игры.
2. **Подготовить локальный `index.html` к проверке** — убедиться, что он подключает все актуальные файлы игры, и сообщить пользователю: «открой `index.html` в браузере (двойной клик)». Пользователь проверяет изменения локально, без сервера.
3. **Подготовить изменения к пушу** — сделать коммит с понятным сообщением на русском и убедиться, что ветка синхронна с `origin/main` (перед коммитом: `git fetch` + `git status`; никогда не переписывать уже запушенные коммиты через `--amend`/rebase). Пользователь пушит сам.
4. **Только после этого** сообщать пользователю: что изменилось, как проверить локально, что проверить на телефоне после пуша.
5. **В конце задачи ВСЕГДА выдать блок с двумя командами для копирования** (одна кнопка — одна команда), с подписями какая для дева, какая для прода:

## Договорённости
- Спрайты/арт: пользователь всегда кладёт новые картинки в `design/assets/characters/`;
  ИИ сам копирует их в `assets/` (игровые ассеты) под именами, на которые ссылается код
- Сжатие спрайтов: перед копированием в `assets/` ИИ сжимает картинку
  (инструмент — `tools/compress_assets.ps1`, NearestNeighbor сохраняет пиксель-арт,
  исходники в `design/` не трогаем). Ориентиры: портреты/карточки — не шире 512px
  и ≤ 200 КБ; листы персонажей — не шире 768px; фон сцены — не шире 720px;
  крупные листы (босс и т.п.) — не шире 1024px. Цель — суммарно ассеты < 3 МБ,
  чтобы игра быстро грузилась на телефоне
- Работаем маленькими шагами: один шаг = одно проверяемое изменение, после каждого — запуск игры
- Числа баланса — только в `js/config.js`
- Комментарии в коде — короткие, на русском
- Дизайн меняет только пользователь / режим «Геймдизайнер»; ИИ сообщает о проблемах, а не меняет молча
- Мобайл-first: после каждого шага проверять на телефоне по ссылке
