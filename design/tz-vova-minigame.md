# Техническое задание: веб-игра «Выживи на совещании» — мини-игра Вовы «Мемы под столом»

Статус: **черновик v1** — на утверждение автором
Источник дизайна: [concept.md](concept.md), [features/vova-minigame.md](features/vova-minigame.md)

---

## 1. Общее описание

### 1.1. Что строим
Одностраничная браузерная игра без установки и регистрации. Игрок открывает сайт по ссылке с телефона (основной сценарий) или с десктопа. Играется одна мини-игра: персонаж Вова на совещании листает мемы на телефоне, пока босс не смотрит. Цель — продержаться 60 секунд, занимаясь «своими делами», и не получить 2 замечания.

### 1.2. Ключевые ограничения
- **Мобайл-first:** основной сценарий — телефон, тач-управление одним пальцем. Десктоп — зажатая кнопка мыши. Оба входа обязательны.
- **Раунд не длиннее 70 секунд** (жёсткое требование автора; целевая длина — 60 с).
- **Один вход:** касание/зажатие в любом месте экрана. Никаких кнопок, жестов, клавиатуры в геймплее.
- **Без бэкенда:** всё работает статикой (GitHub Pages / любой статический хостинг). Шеринг — через системные средства браузера.
- **Без сборки и фреймворков:** vanilla HTML/CSS/JS. Один проект, который можно открыть как статические файлы.

### 1.3. Поток экранов
```
Экран выбора персонажа → Мини-игра (60 с) → Финальный экран → «Ещё раз» (рестарт в 1 тап)
```
В MVP экран выбора персонажа: карточка Вовы (арт готов, см. §8) + 2–3 заблокированных слота «???» (некликабельные, тизер). Тап по карточке Вовы → сразу мини-игра. Обратный путь с финального экрана на экран выбора в MVP не нужен: перезагрузка страницы всегда возвращает на экран выбора.

## 2. Технологический стек и структура проекта

### 2.1. Стек
- HTML5 + CSS3 + vanilla JavaScript (ES2020+), без зависимостей.
- Рендер сцены: **Canvas 2D** (пиксель-арт персонажей, флипчарт, стол).
- UI-элементы (таймер, счётчик, плашки, финальный экран): **DOM поверх canvas** — проще стилизовать и локализовать.
- Ассеты: PNG-спрайты (см. §8). Пиксель-арт рисуется с `image-rendering: pixelated`.

### 2.2. Структура файлов (рекомендуемая)
```
index.html
css/style.css
js/main.js          — точка входа, игровой цикл
js/config.js        — ВСЕ настраиваемые числа и тексты (см. §7)
js/scene.js         — отрисовка сцены (фон, стол, флипчарт, персонажи)
js/boss.js          — конечный автомат босса
js/vova.js          — состояние Вовы, телефон
js/input.js         — pointerdown/pointerup, пауза при уходе с вкладки
js/ui.js            — HUD, плашки, финальный экран, шеринг
assets/characters/vova.png
assets/characters/boss_*.png   — спрайты босса (см. §8)
assets/scene/*.png             — фон, стол, флипчарт-листы
```
Допустимо объединять модули, если проект мал — главное: **весь баланс и тексты в `config.js`**, не в коде.

### 2.3. Требования к совместимости
- Мобильные Safari (iOS 15+) и Chrome/Android (Chrome 90+).
- Вьюпорт: от 320×568 (портрет) до десктопных разрешений. Сцена масштабируется, композиция по центру (см. §5.4).
- `touch-action: none` на игровом поле — страница не скроллится и не зумится во время игры.
- `user-select: none`, отключить контекстное меню по долгому тапу на мобиле.
- Адресная строка и жесты браузера не должны мешать: игра занимает весь вьюпорт (`100dvh`).

## 3. Игровые правила (однозначная формулировка для реализации)

1. **Вход:** `pointerdown` в любом месте окна = телефон Вовы поднимается; `pointerup`/`pointercancel` = телефон опускается. Слушать на `window`, не на конкретном элементе. Мультитач: первый палец управляет, остальные игнорируются.
2. **Показатель «свои дела»:** накапливаем время `phoneUpTime` (сек), пока телефон над столом. Отображаемый процент: `percent = round(phoneUpTime / 60 * 100)`.
3. **Замечание:** в состоянии босса «Смотрит на аудиторию»:
   - телефон был наверху на момент начала «Смотрит» → замечание, ЕСЛИ игрок не отпустил в течение койот-тайма (п. 5);
   - `pointerdown` произошёл уже во время «Смотрит» → замечание, если удержание длится ≥ 0,1 с (койот-тайм здесь не применяется — игрок поднял телефон, когда босс уже смотрит).
4. **Провал:** `warnings == 2` → немедленный переход к финалу «Спалился».
5. **Койот-тайм:** если телефон был наверху на момент начала «Смотрит» и `pointerup` произошёл в течение 0,15 с после начала состояния — замечание не засчитывается (телефон «успел спрятаться»). Койот-тайм имеет приоритет над порогом 0,1 с.
6. **Фальстарт:** состояние, когда босс начал поворот, но смотрит в часы/окно. Не наказывает и не награждает. Появляется с 20-й секунды забега с вероятностью 20% вместо обычного поворота.
7. **Победа:** таймер забега достиг 0 при `warnings ≤ 1`.
8. **Пасхалка:** победа с `phoneUpTime == 0` → отдельная карточка.
9. Игрок не может: ускорить босса, спрятать телефон быстрее 0,3 с, пропустить время, поставить игру на паузу вручную (пауза только автоматическая, §6.5).

### 3.1. Точная семантика поимки (важно для реализации)
- Телефон имеет физическую анимацию подъёма/опускания 0,3 с. Для правил поимки телефон считается «наверху» с момента `pointerdown` (не после анимации) — иначе игрок будет путаться.
- Сценарий А: телефон наверху, босс переходит в «Смотрит». Если `pointerup` в первые 0,15 с («Поворачивается» + начало «Смотрит» считаются от начала «Смотрит») — замечания нет, даже если анимация телефона ещё доигрывается. Если палец всё ещё зажат спустя 0,15 с — замечание.
- Сценарий Б: `pointerdown` во время «Смотрит». Замечание, если удержание ≥ 0,1 с. Койот-тайм не применяется.
- Псевдокод проверки каждый кадр в состоянии `WATCHING`:
  ```
  if phoneUp:
      if phoneUpStartedBeforeWatching and (now - watchingStart) > coyoteSec: warning()
      if not phoneUpStartedBeforeWatching and (now - phoneUpStart) > caughtThresholdSec: warning()
  ```

## 4. Конечный автомат босса

### 4.1. Состояния
| Состояние | Вид на экране | Опасность | Длительность |
|---|---|---|---|
| `AT_FLIPCHART` | Стоит у флипчарта спиной/боком к игроку, жестикулирует, рисует | Безопасно | По фазам, §4.2 |
| `TURNING` | Разворачивает корпус к аудитории | Предупреждение | 0,6 с (первый цикл 0,8 с) |
| `WATCHING` | Лицом к игроку, обводит взглядом, бормочет | **Опасно** | 1–2 с |
| `FAKEOUT` | Начал поворот, но смотрит в часы/в окно | Безопасно | 1–1,5 с |

### 4.2. Переходы и тайминги
```
AT_FLIPCHART → TURNING → WATCHING → AT_FLIPCHART
                    └──→ FAKEOUT → AT_FLIPCHART   (шанс 20%, с 20-й секунды)
```
- Длительность `AT_FLIPCHART` — случайная в диапазоне, зависящем от фазы забега:
  - Фаза 1 (0–20 с): 5–8 с
  - Фаза 2 (20–40 с): 3–5 с
  - Фаза 3 (40–60 с): 2–4 с
- **Первый цикл забега всегда:** 8 с `AT_FLIPCHART` + 0,8 с `TURNING` (обучение, не случайно).
- Длительности `WATCHING` и `FAKEOUT` — случайные в диапазонах из таблицы.
- За 60 с игрок встречает ~8–12 циклов.
- Использовать честный ГПСЧ (`Math.random`); не допускать `FAKEOUT` в двух соседних циклах (если предыдущий цикл закончился фальстартом, следующий `TURNING` ведёт только в `WATCHING`).

### 4.3. Телеграф поворота (обязателен)
Перед переходом `AT_FLIPCHART → TURNING` босс 0,5 с ставит маркер на полку флипчарта и кладёт руку на лист. Это визуальный сигнал для внимательных игроков. Телеграф — последние 0,5 с состояния `AT_FLIPCHART` и **входит в его длительность** (в том числе в фиксированные 8 с первого цикла).

## 5. Сцена и отрисовка

### 5.1. Композиция (вид сбоку)
- Слева за столом сидит **Вова** (лицом вправо, к флипчарту).
- Справа у флипчарта стоит **босс** (спиной/боком к игроку в `AT_FLIPCHART`, лицом к игроку в `WATCHING`).
- Фон: офисная переговорная (стена, окно, стол). Стиль — пиксель-арт, тёмный фон как на референсе Вовы.

### 5.2. Позы Вовы (3 состояния)
| Состояние | Триггер | Спрайт/анимация |
|---|---|---|
| Слушает | касание отпущено | Руки на столе, лёгкий кивок (2 кадра, цикл ~1 с) |
| Листает | касание удерживается | Телефон над коленями, ухмылка; большой палец листает (2 кадра) |
| Пойман | замечание | Замирает на 0,5 с (штраф-оглушение), босс хмурится |

Переход «слушает ↔ листает» мгновенный по входу; анимация телефона (подъём/опускание 0,3 с) — визуальная, поверх состояния.

### 5.3. Анимации босса
- `AT_FLIPCHART`: цикл жестов — тычет маркером в график, рисует линию, перещёлкивает лист (3–4 листа с пиксельными «графиками», смена каждые ~6 с).
- `TURNING`: разворот корпуса (2–3 промежуточных кадра).
- `WATCHING`: лицо к игроку, лёгкое покачивание, плашка-реплика (§5.5).
- `FAKEOUT`: корпус развёрнут, но голова повёрнута к часам на стене/в окно.

### 5.4. Адаптивность
- Сцена рисуется в логических координатах (например, 360×640 портрет) и масштабируется под вьюпорт с сохранением пропорций (letterbox).
- В ландшафте — та же сцена по центру, фон растягивается. Элементы не привязаны к краям экрана. [ПРОВЕРИТЬ В ПРОТОТИПЕ]

### 5.5. Плашки и HUD (DOM)
- **Реплики босса** при `WATCHING`: плашка над боссом, случайная из `bossLines` (5 шт., утверждены, в конфиге §7). Не повторять одну и ту же дважды подряд.
- **Мем-плашки** при листании: всплывают над телефоном Вовы каждые 2–3 с, случайная из `memes` (8 шт., утверждены, в конфиге §7). Плашка живёт ~1,5 с, плавно всплывает и тает.
- **HUD:** таймер «до конца совещания…» (полоска внизу, 60 с) + счётчик «Свои дела: 35%» в углу.
- **Замечание:** красная вспышка на боссе, текст «ЗАМЕЧАНИЕ 1/2» на 1 с, короткая вибрация (`navigator.vibrate(80)`, только Android; на iOS API нет — просто пропустить).

## 6. Управление, ввод, паузы

### 6.1. Ввод
- `pointerdown` / `pointerup` / `pointercancel` на `window`.
- На десктопе дополнительно: `mousedown`/`mouseup` покрываются Pointer Events; клавиатура НЕ используется.
- Любая точка экрана = управление (защита от промаха пальцем).

### 6.2. Обучение (первые 3 с забега)
Плашка: «Держи — Вова листает. Отпусти — босс смотрит». Исчезает при первом `pointerdown` или через 3 с.

### 6.3. Первый цикл
Гарантированно: 8 с `AT_FLIPCHART` + 0,8 с `TURNING` — игрок успевает понять без слов.

### 6.4. Штраф-оглушение
После замечания Вова замирает на 0,5 с (поза «пойман»). В это время ввод игнорируется (телефон не поднимается). Если палец всё ещё зажат после окончания оглушения — телефон поднимается (ввод «догоняет» состояние пальца). [ПРОВЕРИТЬ В ПРОТОТИПЕ] — подтвердить по плейтесту, что не бесит.

### 6.5. Автоматическая пауза
- `visibilitychange` (ушёл с вкладки) или `blur` → пауза: таймеры замирают, оверлей «Совещание без тебя не ждёт. Коснись, чтобы вернуться».
- Возврат по касанию. Забег не сбрасывается.
- Входящий звонок на мобиле = уход с вкладки, покрывается тем же механизмом.

### 6.6. Запрет скролла/зума
`touch-action: none` на игровом контейнере; `preventDefault` на `touchmove` в пассивных слушателях не нужен при корректном CSS, но проверить на iOS Safari.

## 9. Финальный экран

### 9.1. Появление
Через 1 с после конца сцены (пауза, чтобы игрок увидел финальную позу Вовы).

### 9.2. Состав (сверху вниз)
1. **Карточка результата** — человеческой фразой:
   - Победа: «Вова дожил до конца совещания. {Звание}. {P}% рабочего времени занимался своими делами»
   - Провал: «Спалился на {N} секунде» — только эта фраза, без процентов и дополнений.
   - Пасхалка (победа с 0%): «Вова не занялся ни одним своим делом. Босс подозрительно доволен»
2. Дополнение (только для победы): «Замечаний: {k}».
3. Кнопка **«Поделиться»**:
   - Мобайл: `navigator.share({ text, url })` при доступности; иначе fallback — копирование в буфер + плашка «Ссылка скопирована».
   - Десктоп: копирование в буфер (`navigator.clipboard.writeText`) + плашка «Ссылка скопирована».
   - Текст шеринга: из конфига — победа: «Я {P}% совещания занимался своими делами и не попался. Побьёшь?», провал: «Спалился на {N} секунде совещания. Побьёшь?»
4. Большая кнопка **«Ещё раз»** — мгновенный рестарт без меню.

### 9.3. Звания (из конфига)
| % | Звание |
|---|---|
| 0% | пасхалка (отдельная карточка) |
| 1–15% | «Первый раз на совещании?» |
| 16–35% | «Мастер маскировки» |
| 36–55% | «Опытный бездельник» |
| 56%+ | «Легендарный Апёздол» |

## 10. Крайние случаи (обязательны к обработке)
| Случай | Поведение |
|---|---|
| Игрок ни разу не коснулся | Победа с 0% → пасхалка |
| Игрок держит постоянно | 2 замечания → провал (первое — в первый же `WATCHING`) |
| Спам-тапы | Тап ≈ 0,1 с листания — почти не даёт процента; самоуравновешивается |
| Мультитач | Первый палец управляет, остальные игнорируются |
| `pointercancel` (системный жест) | Считать как `pointerup` |
| Уход с вкладки / звонок | Пауза + оверлей возврата (§6.5) |
| Скролл/зум страницы | Запрещены (`touch-action: none`) |
| `navigator.share` недоступен | Fallback: буфер обмена + плашка |
| `navigator.vibrate` недоступен (iOS) | Тихо пропустить |
| Два `FAKEOUT` подряд | Запрещены (см. §4.2) |
| Победа с зажатым телефоном | Победа засчитывается; телефон опускается, сцена финала |
| Рестарт | Полный сброс состояния: таймеры, замечания, процент, автомат босса |

## 11. План реализации (пошагово, для ИИ-разработчика)

Каждый шаг — самостоятельная проверяемая итерация. После каждого шага игра запускается.

1. **Каркас + сцена-заглушка.** `index.html`, canvas, игровой цикл (`requestAnimationFrame`), фон, стол, флипчарт, босс и Вова заглушками (прямоугольники/простые спрайты). Ввод: удержание меняет позу Вовы. *Проверка:* на телефоне и десктопе удержание поднимает телефон, отпускание опускает; страница не скроллится.
2. **Автомат босса.** Состояния по таймингам из `CONFIG`, без фальстартов, первый цикл фиксированный. *Проверка:* босс поворачивается по расписанию, тайминги совпадают с конфигом.
3. **Поимка.** Замечание при телефоне наверху в `WATCHING` (порог 0,1 с, койот-тайм 0,15 с), оглушение 0,5 с, 2 замечания → экран провала (заглушка). *Проверка:* можно специально пойматься дважды и увидеть провал; койот-тайм спасает при быстром отпускании.
4. **Прогресс забега.** Таймер 60 с, счётчик «своих дел» в %, экран победы (заглушка). *Проверка:* полный забег от старта до финала за минуту; процент корректен (проверить: 21 с листания = 35%).
5. **Сложность и хитрость.** Фазы 0–20/20–40/40–60, фальстарты с 20-й секунды (шанс 20%, не подряд), телеграф поворота. *Проверка:* поздний этап ощутимо злее; фальстарт не наказывает.
6. **Финальные экраны и шеринг.** Один шаблон, 3 исхода, звания, «Поделиться» (`navigator.share` / буфер), «Ещё раз», вибрация при поимке и на финале. *Проверка:* все финалы достижимы; шеринг работает на телефоне; рестарт сбрасывает всё.
7. **Полировка и плейтест.** Мем-плашки, реплики босса, смена листов флипчарта, адаптив портрет/ландшафт. Плейтест на 2–3 коллегах обязательно с телефона; правка `config.js` по итогам.

### Приоритеты на случай нехватки времени
Вырезать первым: фальстарты → вибрация → мем-плашки (заменить на 3 заготовки) → смена листов флипчарта (оставить 1 лист). Ядро (ввод, автомат босса, поимка, таймер, финалы) не вырезается никогда.

## 12. Критерии приёмки

### Работает (проверяемо)
- [ ] Удержание поднимает телефон, отпускание прячет за 0,3 с — на тач и на мыши.
- [ ] Ввод работает касанием в любой точке экрана.
- [ ] Босс проходит циклы по таймингам конфига; первый цикл 8 с + 0,8 с.
- [ ] Замечание засчитывается по правилу §3.1; койот-тайм 0,15 с работает.
- [ ] 2 замечания → провал с карточкой «Спалился на {N} секунде».
- [ ] 60 с → победа; карточка со званием и процентом.
- [ ] Победа с 0% → пасхалка.
- [ ] Процент считается корректно (21 с = 35%).
- [ ] Пауза при уходе с вкладки, возврат касанием, забег не сбрасывается.
- [ ] Страница не скроллится и не зумится во время игры.
- [ ] Раунд не длиннее 70 с.
- [ ] Рестарт полностью сбрасывает состояние.
- [ ] Шеринг: `navigator.share` на мобиле, буфер на десктопе.

### Ощущается правильно (плейтест, обязательно с телефона)
- [ ] Игрок понимает механику за первый цикл, без объяснений.
- [ ] Ловит себя на «ещё чуть-чуть» (жадность против страха).
- [ ] Смеётся хотя бы раз (мемы/реплики/пасхалка).
- [ ] После финала хочет перезапустить сразу.
- [ ] Нет случайных замечаний от промаха пальцем.
- [ ] Поворот босса читается без звука.
