# Техническое задание: веб-игра «one ❤ офис» — мини-игра Вовы «Успеть за 60 секунд»

Статус: **утверждено (as-built v2)** — документ отражает фактическое состояние кода `v0.9.35`
Источник дизайна: [concept.md](concept.md), [features/vova-minigame.md](features/vova-minigame.md)
Предыдущая версия: ТЗ v1 (черновик до разработки). Все расхождения v1 → факт собраны в §13.

## 1. Общее описание

### 1.1. Что построено
Одностраничная браузерная игра без установки и регистрации. Игрок открывает сайт по ссылке с телефона (основной сценарий) или с десктопа. Играется одна мини-игра: персонаж Вова на совещании листает мемы на телефоне, пока босс не смотрит. Цель — продержаться 60 секунд, занимаясь «своими делами», и не получить 2 замечания.

Деплой: GitHub Pages — https://artemyakudza-max.github.io/office/

### 1.2. Ключевые ограничения (выполнены)
- **Мобайл-first:** тач-управление одним пальцем; десктоп — зажатая левая кнопка мыши.
- **Раунд ровно 60 секунд** игрового времени; потолок 70 с не нарушается по построению (окно гнева замораживает и игровое время, и таймер забега — см. §3, п. 10).
- **Один вход в геймплее:** удержание в любой точке игрового поля (canvas). Касания UI-элементов (кнопки, оверлеи) телефон не поднимают.
- **Без бэкенда:** статика на GitHub Pages. Шеринг — `navigator.share` / буфер обмена.
- **Без сборки и фреймворков:** vanilla HTML/CSS/JS (ES2020+), подключение `<script>` в `index.html`.
- **Весь баланс и тексты — в `js/config.js`**, ни одного магического числа в логике.

### 1.3. Поток экранов (фактический)
```
Экран выбора персонажа → Мини-игра (60 с) → Финальный экран → «Ещё раз» (рестарт в 1 тап)
                                    ↑                              │
                                    └──── «Главное меню» ←─────────┘
```
- Экран выбора: карточка Вовы («Успеть за 60 секунд») + 2 заблокированных слота «Скоро».
- Из паузы и с финального экрана есть возврат на экран выбора («Главное меню») — расширение относительно ТЗ v1.
- Обучение показывается только в первом забеге сессии (после рестарта — не показывается).

## 2. Технологический стек и структура проекта (фактическая)

### 2.1. Стек
- HTML5 + CSS3 + vanilla JavaScript (ES2020+), без зависимостей (кроме Google Fonts «Press Start 2P»).
- Рендер сцены: **Canvas 2D**. Спрайты PNG с `image-rendering: pixelated`; при недоступности файла — фолбэк на код-арт (игра не ломается).
- UI: **DOM поверх canvas** (`#ui` с `pointer-events: none`; интерактивные элементы включают `pointer-events: auto`).
- Игровой цикл: `requestAnimationFrame` с delta time (dt ограничен 0,1 с — защита от скачка после сна вкладки).

### 2.2. Структура файлов
```

js/vova.js                  — состояние Вовы: телефон, поимка, блокировка
```

### 2.3. Совместимость
- Мобильные Safari (iOS 15+) и Chrome/Android; десктопные браузеры.
- Сцена: логические координаты 360×640 (портрет), letterbox-масштаб под вьюпорт; фон тянется на весь экран и в портрете, и в ландшафте.
- `touch-action: none`, `user-select: none`, `-webkit-touch-callout: none`, запрет контекстного меню по долгому тапу.
- Вибрация: `navigator.vibrate` (Android); на iOS API нет — тихо пропускается.

## 3. Игровые правила (по коду, однозначно)

1. **Ввод:** `pointerdown` на canvas (левая кнопка / тап) = телефон поднимается; `pointerup`/`pointercancel` = опускается. Мультитач: первый палец управляет, остальные игнорируются. Касания не-canvas элементов (кнопки, оверлеи) игнорируются.
2. **Показатель «свои дела»:** накапливается `phoneUpTime` (сек), пока телефон наверху. Отображаемый процент: `percent = round(phoneUpTime / 60 * 100)`.
3. **Минимальные времена состояний (защита от спама двумя пальцами):** телефон не опустится раньше `minUpSec = 0,4 с` после подъёма и не поднимется раньше `minDownSec = 0,2 с` после опускания. Спам даёт длинные периоды «наверху», которые ловятся, и почти не даёт процента.
4. **Замечание (поимка)** — только в состоянии босса `WATCHING`, проверка каждый кадр:
   - Телефон был наверху **до** начала «Смотрит» → замечание, если босс смотрит дольше `coyoteSec = 0,15 с` (койот-тайм: быстрое отпускание спасает).
   - Телефон поднят **во время** «Смотрит» → замечание, если удержание длится дольше `caughtThresholdSec = 0,1 с`. Койот-тайм не применяется.
   - Койот-тайм имеет приоритет над порогом 0,1 с.
5. **Последствия замечания:**
   - Вибрация 80 мс (если доступна).
   - Телефон принудительно спрятан и **заблокирован** (`locked`): ввод игнорируется, пока босс не отвернётся от аудитории (состояние перестало быть `WATCHING`). После разблокировки зажатый палец «догоняет» — телефон поднимается сразу.
   - **Окно гнева босса** `angrySec = 2,5 с`: красный оверлей с гневной фразой (случайная из `bossAngryLines`) и строкой «ЗАМЕЧАНИЕ k/2». Игра полностью заморожена (`frozen`): таймеры, автомат босса и процент стоят — это штраф «−2,5 сек игрового времени».
6. **Провал:** 2-е замечание → окно гнева 2,5 с → финальный экран «fail» (вибрация 200 мс).
7. **Фальстарт (`FAKEOUT`):** босс развернулся к аудитории, но смотрит в часы/окно. Не наказывает и не награждает. Появляется с 20-й секунды забега с вероятностью 20% вместо обычного поворота; два фальстарта подряд запрещены.
8. **Победа:** `roundTime ≥ 60` при `warnings ≤ 1` → пауза 1 с (игрок видит финальную позу) → финальный экран «win» (вибрация 200 мс). Победа с зажатым телефоном засчитывается.
9. **Пасхалка:** победа с `percent == 0` (ни разу не поднял телефон) → отдельная карточка «easter».
10. Игрок не может: ускорить босса, поднять телефон во время блокировки, потерять время из-за пауз (пауза замораживает всё игровое время).

### 3.1. Псевдокод проверки поимки (реализован в `vova.js → checkCaught`)
```
if phoneUp:
    if phoneUpStart < (gameTime - watchingElapsed):        // был наверху до «Смотрит»
        caught = watchingElapsed > coyoteSec               // 0,15 с
    else:                                                  // поднял во время «Смотрит»
        caught = (gameTime - phoneUpStart) > caughtThresholdSec  // 0,1 с
```

## 4. Конечный автомат босса (реализован в `boss.js`)

### 4.1. Состояния
| Состояние | Вид на экране | Опасность | Длительность |
|---|---|---|---|
| `AT_FLIPCHART` | Стоит у флипчарта спиной/боком, жестикулирует, рисует | Безопасно | По фазам, §4.2 |
| `TURNING` | Разворачивает корпус к аудитории | Предупреждение | 0,6 с (первый цикл 0,8 с) |
| `WATCHING` | Лицом к игроку, скрещенные руки, покачивание, реплика | **Опасно** | 1–2 с |
| `FAKEOUT` | Развёрнут, но зрачки подняты к часам/окну | Безопасно | 1–1,5 с |

### 4.2. Переходы и тайминги
```
AT_FLIPCHART → TURNING → WATCHING → AT_FLIPCHART
                    └──→ FAKEOUT → AT_FLIPCHART   (шанс 20%, с 20-й секунды, не два подряд)
```
- Длительность `AT_FLIPCHART` — случайная в диапазоне по фазе забега:
  - Фаза 0 (0–20 с): 5–8 с
  - Фаза 1 (20–40 с): 3–5 с
  - Фаза 2 (40–60 с): 2–4 с
- **Первый цикл забега всегда:** 8 с `AT_FLIPCHART` + 0,8 с `TURNING` (обучение, не случайно).
- За 60 с игрок встречает ~8–12 циклов.
- Фальстарт: `roundTime ≥ 20` И предыдущий цикл не был фальстартом И `Math.random() < 0,2`.

### 4.3. Телеграф поворота
Последние `telegraphSec = 0,5 с` состояния `AT_FLIPCHART` — босс ставит маркер на полку (`Scene.bossTelegraph`). Телеграф входит в длительность `AT_FLIPCHART` (в том числе в фиксированные 8 с первого цикла).

## 5. Сцена и отрисовка (фактическое, `scene.js`)

### 5.1. Сеттинг и композиция
Переговорная agile-офиса ВТБ в Москва-Сити (референс skaz.design/vtb: графит + синие акценты бренда, гексагоны, окно с ночным кластером башен «Федерация»/«ОКО»/«Меркурий», река с отражениями, луна, звёзды; настенные часы — на них смотрит босс в фальстарте; доска KPI, ковролин, тёплые лампы).
- Слева за столом сидит **Вова** (лицом вправо, к флипчарту).
- Справа у флипчарта стоит **Лена — босс**: блондинка в синей футболке и джинсах (спрайт `boss_states.png`; спиной/боком в `AT_FLIPCHART`, лицом к игроку в `WATCHING`/`FAKEOUT`). Далее по документу «босс» — роль в автомате состояний.
- Флипчарт привязан к боссу (`bossGap = 0,75` ширины босса правее его центра), рисуется до босса — «за спиной».

### 5.2. Спрайты (вариант B) и фолбэк
| Спрайт | Файл | Кадры | Использование |
|---|---|---|---|
| Фон | `assets/sprites/bg_office.png` | 1 | Cover-fit по видимой области; края обрезаются в портрете |
| Вова | `assets/sprites/vova_poses.png` | 3: слушает / телефон / пойман | Кадр по состоянию: `locked` → 2, `phoneUp` → 1, иначе 0 |
| Лена (босс) | `assets/sprites/boss_states.png` | 4: спиной у флипчарта, пишет маркером / поворот / смотрит, руки в боках / фальстарт — смотрит на часы | Кадр по состоянию автомата |
| Флипчарт | `assets/sprites/flipchart.png` | 4 листа «доклада» | `Boss.cycleCount % 4` — лист меняется каждый цикл |

- Если файл не загрузился — рисуется код-арт (пиксель-арт прямо в `scene.js`): комната по слоям, персонажи, флипчарт с 4 вариантами графиков (`drawChart`). Игра не ломается. [ДОПУЩЕНИЕ] Код-арт фолбэк босса — лысый мужчина в костюме (заглушка), не совпадает с Леной из спрайта; на проде спрайт всегда грузится, фолбэк — только страховка.
- Позиционирование — **якорные доли** из конфига: `fx` (центр, доля ширины фона), `fy` (линия ног, доля высоты), `hFrac` (высота, доля опорной высоты). Опорная высота `unitH = min(dh, dw * 1,5)` — защита от гигантских персонажей на вытянутом портрете.

### 5.3. Адаптивная раскладка
- Прямоугольник привязки персонажей = пересечение фона с видимой областью (`anchorRect`).
- Узкий экран (`dw < 500`, мобайл): Вова у левого края, флипчарт у правого, босс вплотную к флипчарту.
- Широкий экран (десктоп): позиции по долям `fx` из конфига.
- Плашки (мемы/реплики): на мобайле прижимаются к краю экрана на высоте головы, на десктопе — по центру над головой (`bubbleAnchor`).

### 5.4. Позы Вовы
| Состояние | Триггер | Кадр |
|---|---|---|
| Слушает | касание отпущено | 0 (кивок) |
| Листает | касание удерживается | 1 (телефон, палец листает) |
| Пойман | замечание, до отворота босса | 2 (телефон замер у лица, глаза шире) |

Переход «слушает ↔ листает» мгновенный по вводу (с учётом minUpSec/minDownSec, §3 п. 3).

## 6. Управление, ввод, паузы, обучение (фактическое)

### 6.1. Ввод
- `pointerdown` / `pointerup` / `pointercancel` на `window`, но управление телефоном — **только касания canvas** (`e.target.tagName === "CANVAS"`).
- Только левая кнопка мыши (`e.button === 0`) / тап.
- Мультитач: первый палец (`pointerId`) управляет, остальные игнорируются.
- `pointercancel` (системный жест, звонок) = как отпускание.
- Контекстное меню по долгому тапу запрещено.
- `Input.reset()` вызывается при выходе из пауз/обучения — касание возврата не поднимает телефон.

### 6.2. Обучение (первый забег сессии)
- Игра **стоит на паузе** (`tutorialDone = false`), сцена видна, таймеры не идут.
- Плашка «ПРАВИЛА» с 6 строками из `CONFIG.rules` (эмодзи + короткие правила, включая подсказку про фальстарт «смотрит на часы»).
- Исчезает **только при первом касании** (не по таймеру); касание закрытия не поднимает телефон.
- Плашка сворачивается анимацией в кнопку «ПРАВИЛА» (0,4 с).
- В последующих забегах (после «Ещё раз») обучение не показывается — правила доступны по кнопке.

### 6.3. Первый цикл
Гарантированно: 8 с `AT_FLIPCHART` + 0,8 с `TURNING` — игрок успевает понять без слов.

### 6.4. Кнопки во время игры (правый верхний угол)
- **Пауза** (иконка «две палки»): меню «ПАУЗА» с кнопками «Продолжить» / «Главное меню»; тап вне карточки тоже продолжает.
- **ПРАВИЛА** (золотая кнопка под паузой): пауза + окно правил (тот же текст, что в обучении), закрытие кнопкой «Играть» или тапом вне карточки.

### 6.5. Автоматическая пауза
- `visibilitychange` (ушёл с вкладки) или `blur` → пауза: таймеры замирают, оверлей «Все ждут только тебя, Вова. Коснись, чтобы вернуться».
- Возврат по касанию оверлея (не по `window` — иначе клики по кнопкам меню паузы снимали бы паузу). Забег не сбрасывается.
- На экране выбора автопауза не применяется.

### 6.6. Запрет скролла/зума
`touch-action: none` на `html/body` и `#game`; `overflow: hidden`; зум отключён метатегом viewport.

## 10. Финальные экраны и шеринг (фактическое, `ui.js → showFinal`)

### 10.1. Появление
- Победа: через 1 с после конца забега (игрок видит финальную позу) + вибрация 200 мс.
- Провал: после окна гнева 2,5 с + вибрация 200 мс.

### 10.2. Состав карточки (один шаблон, три исхода)
Общее: карточка с золотой рамкой (провал — красная, пасхалка — синяя), **портрет-«вспышка» сверху** (132×132, наполовину выходит за верх карточки, ступенчатый пиксель-эффект `finalPop`), кнопки «Поделиться» / «Ещё раз» / «Главное меню».

| Исход | Содержимое |
|---|---|
| **win** | «СОВЕЩАНИЕ ОКОНЧЕНО» → крупный `{P}%` → «рабочего времени Вова занимался своими делами» → разделитель → «ВАШ РАНГ» → звание → «Замечаний: {k}» |
| **fail** | «ЗАМЕЧАНИЙ: 2» → «Выгнали с совещания на {N} секунде. И, возможно, даже лишили премии.» |
| **easter** (победа с 0%) | «СОВЕЩАНИЕ ОКОНЧЕНО» → «Вова не занялся ни одним своим делом на совещании. Что это с ним сегодня?» |

### 10.3. Звания (победа)
| % | Звание |
|---|---|
| 0% | пасхалка (отдельная карточка) |
| 1–15% | «Первый раз на совещании?» |
| 16–40% | «Среднестатистический зевака» |
| 41–67% | «Опытный бездельник» |
| 68–100% | «Легендарный Апёздол» |

### 10.4. Шеринг
- Мобайл: `navigator.share({ text: текст + " " + url })` — ссылка вкладывается в текст (iOS выбрасывает поле `url` при отправке в мессенджеры). Отмена игроком — не ошибка.
- Десктоп / нет `navigator.share`: копирование в буфер (`navigator.clipboard.writeText`) + тост «Ссылка скопирована» (или «Не удалось скопировать»).
- Тексты из конфига: победа — «Я {P}% совещания занимался своими делами и не попался. Побьёшь?», провал — «Выгнали с совещания на {N} секунде. Позор», пасхалка — «Вова умудрился прослушать совещание полностью. WTF?».

## 11. HUD и плашки (фактическое)

- **Бейдж «Свои дела: N%»** (левый верхний угол): пиксель-панель с золотой рамкой, иконка 📱 с лёгким покачиванием; значение пульсирует при изменении процента (не каждый кадр).
- **Полоска таймера** (внизу, 8 px): оставшееся время, зелёная → красная при < 10 с.
- **Версия игры** (правый нижний угол, мелко).
- **Реплики босса** при входе в `WATCHING`: плашка над боссом, случайная из `bossLines` (10 шт.), не повторяется дважды подряд.
- **Мем-плашки** при листании: каждые 2–3 с (`2 + Math.random()`), случайная из `memes` (17 шт.), не повторяется подряд; всплывают и тают за `bubbleSec = 1,8 с`.
- **Окно гнева** при замечании: красный оверлей, случайная гневная фраза из `bossAngryLines` (10 шт.) + «ЗАМЕЧАНИЕ k/2», висит `angrySec = 2,5 с`.

## 12. Крайние случаи (реализованы)

| Случай | Поведение |
|---|---|
| Игрок ни разу не коснулся | Победа с 0% → пасхалка |
| Игрок держит постоянно | 2 замечания → провал (первое — в первый же `WATCHING`) |
| Спам двумя пальцами | minUpSec/minDownSec: длинные периоды «наверху» ловятся, процента почти нет |
| Мультитач | Первый палец управляет, остальные игнорируются |
| `pointercancel` (системный жест) | Считать как `pointerup` |
| Уход с вкладки / звонок | Автопауза + оверлей возврата; забег не сбрасывается |
| Скролл/зум страницы | Запрещены (`touch-action: none`, `overflow: hidden`) |
| `navigator.share` недоступен | Fallback: буфер обмена + тост |
| `navigator.vibrate` недоступен (iOS) | Тихо пропустить |
| Два `FAKEOUT` подряд | Запрещены |
| Победа с зажатым телефоном | Засчитывается |
| Рестарт («Ещё раз») | Полный сброс: таймеры, замечания, процент, автомат босса, ввод; обучение не показывается |
| Спрайт не загрузился | Фолбэк на код-арт, игра не ломается |
| Скачок dt (вкладка спала) | dt ограничен 0,1 с |
| Касание кнопок/оверлеев | Телефон не поднимается (`Input.reset()` + фильтр по canvas) |

## 14. Открытые вопросы (актуальные)

- [ПРОВЕРИТЬ В ПЛЕЙТЕСТЕ] Окно гнева 2,5 с: не ощущается ли слишком долгим при частых замечаниях.
- [ПРОВЕРИТЬ В ПЛЕЙТЕСТЕ] Читаемость телеграфа (маркер на полке) и фальстарта (зрачки к часам) без звука на маленьком экране.
- [ДОПУЩЕНИЕ] Код-арт фолбэк босса (лысый мужчина) не совпадает с Леной из спрайта — допустимо как страховка, на проде не виден.
